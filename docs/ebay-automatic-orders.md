# Automatic eBay order updates

The Pending eBay Orders page shows **eBay automatic sync**, the latest completed automatic run, and any connection error. The server checks the existing eBay account roughly every five minutes even when no browser is open. **Sync now** queues an early check; **Check & reload orders** refreshes the displayed queue. Status polling never reloads orders or replaces an open edit automatically. Administrators can pause/resume; pausing allows a running import to finish.

The worker reuses the existing awaiting-shipment import, cancellation evidence, local open-order reconciliation, stock reservations, and background finance queue. It looks back 90 days and reads up to 1,000 orders, with 50 cancellation-detail checks and up to 120 missing local-order checks per run. Reaching the order cap fails visibly before import rather than claiming a complete sync. This is an operational pending-order sync, not a full historical order archive. Postage, refunds, cancellations on eBay, physical stock deductions, and final fulfillment still require their existing staff workflows.

Automatic and manual imports share a ten-minute lease; dispatch tokens are single-use and are never exposed to browser clients. Expired leases recover on the next scheduler run. Failed runs retain the last success timestamp and retry after five minutes. Line upserts recheck closed/partially fulfilled state in the database and preserve stock links, completed quantities, notes, and unrelated metadata. Manual API calls require an authenticated inventory staff session; trusted server calls keep their existing service-role authentication. Finance and live-capture evidence checks retain their separate existing leases.

Deploy only `20261025230000_ebay_automatic_order_sync.sql`, publish the updated Pending Orders and Stock clients, and deploy `ebay-order-sync` with its existing gateway setting (`verify_jwt=false`; the function checks each supported request type). The migration creates the schedule disabled at the application level. After deployment, an administrator chooses **Resume auto sync**, or deployment sets the singleton enabled and next_sync_at to now, then dispatches it. Existing eBay OAuth secrets are reused; no new grant or credentials are required. Do not replay unrelated migrations.
